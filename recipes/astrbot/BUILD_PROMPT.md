# 重建 AstrBot：工作说明

## 目标和证据等级

为个人、开发者和团队重建一个自托管 AI Agent 聊天机器人平台。用户通过网页聊天或已配置的即时通信平台对话，管理员配置模型、机器人、知识库、插件和自动任务；开发者可以扩展消息处理和工具。复现基线已有可观察行为，保护现存用户数据和插件生态；对上游未解决缺陷增加明确的正确性目标。提案只作为演进约束，不默认要求按 RFC 实现或视为已完成。具体依据见 `UPSTREAM.md`。

基线为 4.29.3 / `abf683071952375ec36baa4cad6b6f3d9c9bb03f`，来自 README、`pyproject.toml`、CLI、Dashboard API 路由、OpenAPI 和测试文件的静态观察。没有启动软件、实际接入平台、测量性能或验证每一项；文中的验收要求是重建目标，不是宣称上游已通过。

## 语言和运行边界

- 优先保留 Python 后端、Vue/TypeScript WebUI，以便兼容现有扩展；若重建者选择其他语言，必须先证明 API、持久化、扩展生态和部署行为的兼容，不得仅凭内部实现替换宣称兼容。基线 `pyproject.toml` 要求 Python 3.12 及以上；上游开发说明中的 3.10+ 与此冲突，以实际构建声明为当前基线。
- 目标是 Linux、Windows、macOS 的 x86-64 / ARM64；基线开发文档提出这些平台，但每种组合是否实际支持和最低系统版本待验证。支持自托管进程和容器；桌面客户端、启动器是独立项目，不视为本配方已包含。
- WebUI 当前源码包含 `zh-CN`、`en-US`、`ru-RU`、`ja-JP` 的语言选项；提供切换、持久化和缺失翻译回退。文档 README 还包含其他语言，不能误称 UI 已完整支持它们。时区、地区格式、RTL 和翻译覆盖率待验证。
- 模型 API、即时通信平台凭据、网络、插件仓库、沙盒运行时和存储是外部前提；无外部服务时应提供明确的未配置、不可用或模拟状态。不得携带源目录 `data/`、会话、凭据、`.env`、本地 `.memsearch` 或私有资料。

## 核心行为

1. **初始化和运维**：CLI 提供 `init`、`run`、`help`、`plug`、`conf`、`password`；首次初始化和后续重启有明确输出，配置和数据保留在持久化目录。区分初始化、已有实例、无效配置、依赖缺失和失败退出。提供开发、容器及常规部署说明。
2. **消息平台**：基线 README 列出 QQ、OneBot v11、Telegram、企业微信、微信公众号、飞书、钉钉、Slack、Discord、LINE、Satori、KOOK、Misskey 和 Mattermost；WhatsApp 标注为将支持，Matrix 等为社区适配器。按平台规范连接、接收并发送文本和受支持的多媒体，维护来源、会话、群/私聊和用户身份，提供连接状态、权限、重连和错误提示；不要承诺各平台能力完全一致。
3. **对话和 Agent**：接收消息后执行访问控制、唤醒/限流、插件处理、模型调用和回复；会话历史、人格、模型和配置按适当作用域绑定，跨会话不能串数据。支持模型流式与非流式结果、工具调用、停止、失败和历史裁剪/压缩。处理图片、音频或文件前检查模型和平台能力，不能把格式不兼容的消息悄悄发到提供商。
4. **模型及工具**：按配置接入 OpenAI 兼容、Anthropic、Gemini 等模型及上游声明的其他提供商，并保留 LLM、嵌入、语音输入/输出等类型区别。支持 MCP、Skills、工具调用及外部 Agent 平台；工具的授权、调用和回执须与当前配置和会话一致。密钥不得出现在普通日志和浏览器可读响应中。
5. **知识库**：创建和管理知识库、上传/解析文档、切分/索引、检索并用于对话；状态和失败原因可见。存储关闭后释放连接和工作线程；删除与重建索引要维持数据一致性。向量服务和嵌入模型如使用外部系统，应明确配置和失败方式。
6. **插件**：浏览、安装、更新、启停和卸载插件，兼容基线插件注册、命令、事件和钩子；清楚呈现安装与依赖错误。插件权限、进程隔离和 SDK 设计参考 RFC #3210，但目前是修订中的提案，不能假设基线默认隔离，更不能把进程隔离等同于完整安全沙箱。明确旧插件兼容策略，避免插件故障损坏其他会话或核心状态。
7. **管理界面和 API**：提供登录/初始化、会话聊天、机器人和平台、模型、人设、配置、知识库、插件、工具、Skills、定时任务、备份、日志及状态。基线提供 `/api/v1` API、旧版认证路由以及 OpenAPI 规范；保留已公开的路径、方法、认证、字段、错误和流式行为。初始化阶段没有逐条摘录全部路径与操作，重建前须从固定提交 `openspec/openapi-v1.yaml` 逐项建立可分发的 Markdown 接口契约并核对旧接口、鉴权作用域；不得假设当前描述足以实现逐接口兼容。
8. **数据与安全**：用户配置、对话、任务和知识库必须明确持久化和迁移，重启不丢失；备份恢复要能实际还原，敏感数据最小暴露。避免路径穿越、越权、请求伪造、无授权文件或技能上传；对所有边界做权限校验。已有漏洞是否在基线存在、是否修复必须单独验证。
9. **任务和主动行为**：支持计划任务及面向指定会话的主动发送，区别计划触发和伪造用户消息，保证对话历史与实际发送一致；取消后不能继续启动新的模型请求。主动消息 RFC #3497 已关闭，但关闭本身不证明提案全部实现。

## 用户体验

基线是 Web 管理界面和独立聊天页面，存在配置表单、聊天流、插件市场及功能导航；基于源码和 README 静态观察，未对真实页面做视觉验收。保留清晰的功能分组、状态反馈与错误提示，包含空、加载、失败、未配置和窄屏状态；支持键盘操作、表单标签和可读对比度。实际布局、品牌、色彩、字体和动效应在运行原版后采集证据，不得凭空写成原版视觉规范。

## 可靠性改进和边界

在保持可解释兼容性的前提下，将 `UPSTREAM.md` 的候选故障转成可复现的测试场景：工具回执配对、模型多模态能力、取消、会话队列容量、权限和资源释放。为可配置队列定义最大等待数量、超时和溢出反馈；不得静默放大积压。对于 RFC 中尚未定案的协议、插件隔离、工作流图形编排、市场分类，先保持扩展空间并记录待决选择，不强行引入不兼容格式。

性能：无真实基线或数字目标。后续在记录硬件、平台、数据规模、负载和模型端延迟的条件下，测量启动、并发会话、排队、内存、知识库索引和重启；未测不得宣称达到性能指标。
